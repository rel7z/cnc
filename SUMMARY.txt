🚀 USAGE EXAMPLES
══════════════════════════════════════════════════════════════════════════════

START SERVER:
   $ ./cnc-server -config server_config.json

START WORKER:
   $ ./cnc-worker -config worker_config.json

SUBMIT JOB (Domain Resolution):
   $ curl -X POST http://localhost:8080/api/jobs \
       -H "Content-Type: application/json" \
       -d '{
         "job": {
           "name": "resolve_domains",
           "type": "domain_resolve",
           "input_file": "domains.txt",
           "output_dir": "./results",
           "split_size": 10485760,
           "workers": []
         }
       }'

CHECK STATUS:
   $ curl http://localhost:8080/api/stats | jq
   $ curl http://localhost:8080/api/workers | jq
   $ curl http://localhost:8080/api/jobs | jq

VIEW RESULTS:
   $ ls -lh results/
   $ cat results/resolved_*.txt

🔧 TECHNICAL HIGHLIGHTS
══════════════════════════════════════════════════════════════════════════════

ARCHITECTURE:
   • Master-Worker pattern
   • TCP for worker connections (persistent, bidirectional)
   • HTTP REST API for clients (stateless)
   • JSON message protocol
   • Goroutines for concurrency
   • Channels for task queue

KEY ALGORITHMS:
   • Line-aware file splitting (bufio.Scanner)
   • Parallel DNS lookups (100 goroutines)
   • Concurrent IP scanning (1000 workers)
   • Task dispatching with load balancing
   • Heartbeat-based health monitoring
   • Retry with exponential backoff

CONCURRENCY:
   • Server: taskDispatcher + heartbeatChecker goroutines
   • Worker: messageLoop + heartbeatLoop + statsReporter + task executors
   • Mutex protection for shared state
   • Context-based cancellation

══════════════════════════════════════════════════════════════════════════════
🎓 KEY LEARNINGS & INSIGHTS
══════════════════════════════════════════════════════════════════════════════

1. TCP COMPLEXITY:
   • Full-duplex doesn't mean no blocking
   • Concurrent writes need careful synchronization
   • Encoder/decoder not thread-safe by default
   • Connection state management is tricky

2. DESIGN DECISIONS:
   • TCP chosen for persistent worker connections
   • HTTP for request-response client API
   • JSON for simplicity (at cost of size)
   • In-memory state (simple, but not persistent)

3. TESTING IMPORTANCE:
   • Integration test caught the blocking issue
   • Need comprehensive unit tests
   • Load testing would reveal more issues

4. DOCUMENTATION VALUE:
   • Extensive docs help maintainability
   • Technical docs crucial for AI assistants
   • Status tracking prevents duplicate work
